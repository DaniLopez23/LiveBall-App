# Local Docker Deployment

This setup runs LiveBall locally with Docker Compose in a production-like layout:

- `frontend-react`: React + Vite static build served by Nginx on `http://localhost:5173`
- `backend-fastapi`: FastAPI + Uvicorn on `http://localhost:8000`
- `match-simulator`: Python XML feed simulator
- `shared-volume`: Docker volume mounted at `/shared` in backend and simulator

## Run

```bash
docker compose up --build
```

The simulator writes these files into the shared volume:

- `/shared/f24-simulated-data.xml`
- `/shared/f9-simulated-data.xml`
- `/shared/F40-squad-23.xml`
- `/shared/f42-23-2023-results.xml`

FastAPI reads those same paths through environment variables:

- `LIVE_XML_PATH` / `F24_XML_PATH`
- `F9_XML_PATH`
- `F40_XML_PATH`
- `F42_XML_PATH`

The frontend uses browser-facing URLs:

- `VITE_API_URL=http://localhost:8000`
- `VITE_WS_URL=ws://localhost:8000/api/v1`
- `VITE_WS_BASE_URL=ws://localhost:8000/api/v1`

The game WebSocket URL generated by the frontend is:

- `ws://localhost:8000/api/v1/ws/games/{game_id}`

## Health Check

```bash
curl http://localhost:8000/health
```

Expected response:

```json
{"status":"ok"}
```

## Configuration

Copy `.env.example` to `.env` if you want to override ports, XML paths, CORS origins, simulator speed, or write interval. Frontend `VITE_*` variables are compiled into the image at build time, so rebuild the frontend image after changing them.

The local Docker volume is intentionally isolated from absolute machine paths so it can later be replaced by an AWS EFS mount.

See [docker-production-readiness.md](docker-production-readiness.md) for the fuller production-readiness notes.
